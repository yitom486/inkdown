## 架构总览（定稿）

三层职责，**互不抢活**：

```
┌─────────────────────────────────────────────────────────────┐
│ ① 静态 Skill（INKDOWN_STATIC_SKILL）                         │
│    产品介绍 + 软启发 + 何时用/不用工具 + turn-context 说明   │
│    → 每条 prompt 固定前缀，字节不变，利于 Provider cache      │
├─────────────────────────────────────────────────────────────┤
│ ② 动态 turn-context（拼在【用户消息】前）                      │
│    轻量：当前文件、阅读位置、是否刚换文件                       │
│    → 换文件必带；每 N 轮（默认 5）带一次                       │
├─────────────────────────────────────────────────────────────┤
│ ③ 按需 MCP 工具（进程内 HTTP，127.0.0.1）                      │
│    只补电子书/PDF 缺口：TOC / 视口 / 当前章 / 指定章 / 检索 / 选区 │
│    → Agent 自行判断调用；Client 从内存序列化，【不写盘】         │
└─────────────────────────────────────────────────────────────┘
```

**明确不做**：

- 用户可见/可配的 MCP UI（server 随 ACP 连接起停，用户无感）  
- 让 Codex 解析 `.epub/.pdf/.mobi` 二进制  
- 用 Inkdown 工具替代 `.md/.txt` 的普通文件读写  
- 强制每轮调工具（会削弱模型通用能力）  
- 在静态 Skill 里塞进度、路径、TOC（打穿 cache）  
- 解析结果多处复制；**内存一份**，按需序列化

## Skill 原则（定稿）

1. **软启发，非强制**  
   用户多半对着当前窗口内容提问；可根据 turn-context **自行判断**是否调工具。  
   能直接答就直接答；不要为「证明用了工具」而空转。

2. **工具只补盲点**  
   | 格式 | 取内容方式 |
   |------|------------|
   | EPUB / MOBI / AZW / PDF | Inkdown MCP 工具（禁止自行解析二进制） |
   | Markdown / TXT 等纯文本 | Agent **原生**读工作区文件；不必走 Inkdown 工具 |

3. **Skill 正文用英文；回复语言跟用户**  
   规则用英文写（跟从更稳、便于产品国际化）。  
   Skill 内写明：match the user's latest message language——**Skill 语言 ≠ 输出语言**。  
   **不**硬编码「默认简体中文」。

4. **Skill 只列已上线的工具**  
   避免 Agent 说「只有 toc」或幻想尚未实现的 API。新工具上线时同步改 Skill 与 MCP `tools/list`。

5. **正文读取：看上下文是否可能已够，不靠「窗口变更」信号**  
   可能已够 → 直接答；不够 →（有 `hasSelection` 则近乎必读选区）→ 视口 → 整章。  
   提示重点是「为何不必每轮重读」（线程里可能已有正文），而非判定「是否同窗」。  
   **不做** `viewportChanged`。数据类提问尤应遵守，避免整章撑爆上下文。

## 实测结论（传输层）

2026-08-30：

- ACP `fs/read_text_file` 在 **codex-acp 下模型不会主动走**（读文件靠 shell）。  
- **进程内 MCP** 实测成功：`initialize` → `tools/list` → `tools/call`，目录 80 条可用。  
- Skill **有效**（会遵守「不要自己解析 EPUB」）；失败曾是传输层，不是提示词。  
- **虚拟 fs 代码保留**，供未来遵守 ACP fs 的运行时；MCP 复用同一条快照回路。  
- **CLI 方案**（`inkdown toc`）作后备，端点可共用。

## Codex / 用户侧期望 ↔ 计划映射

Agent 曾表述过的缺口（「只有 toc；没有正文 / 跳转 / 书签 / 批注」）与优先级：

| 期望 | 状态 | 说明 |
|------|------|------|
| 完整目录 | ✅ `inkdown_get_toc` | 已验收 |
| 当前章正文 | ✅ `inkdown_get_current_text` | 已实机验证 |
| 当前视口 | ✅ `inkdown_get_viewport` | 约一屏；EPUB/MOBI 可见块，PDF 当前页 |
| 全书检索 | ✅ `inkdown_search` | 待验 |
| 用户选区 | ✅ `inkdown_get_selection` + turn-context `hasSelection` | 待验 |
| 指定章正文 | ✅ `inkdown_get_chapter` | 按 flatIndex / 标题；不跳转 |
| 跳转章节 | ⏸ 延后封闭 | 用户自己用目录跳转即可；Agent 暂不提供写导航 |
| 书签 / 批注读写 | ✅ `inkdown_list_marks` / `create_bookmark` / `create_note` | 列表 + 当前位置书签 + 选区批注 |
| 选区「问 Agent」 | ✅ SelectionToolbar | 强制开面板并聚焦；复用 sticky 选区 |

**原则**：先把「可读文本」做厚（目录 / 当前章 / 检索 / 指定章）；**导航与批注是写能力**，放后做，避免和「只读补盲」混在一起。

## 风险

| 风险 | 对策 |
|------|------|
| Skill 写太死 → 模型每轮空转工具 | **软启发**；工具描述写清「可选 / 能直接答则不必」 |
| Skill 列未上线工具 → Agent 幻觉或自称不可用 | Skill 与 `tools/list` 同步；只写已上线项 |
| md/txt 也调 Inkdown 工具 | Skill 表格明示；工具描述再挡一层 |
| Codex 忽略 turn-context | `documentChanged` + `tocTopLevel` 粗大纲；完整结构走 `inkdown_get_toc` |
| 断开连接卡死 | MCP `closeAllConnections` + 连接作用域生命周期 |
