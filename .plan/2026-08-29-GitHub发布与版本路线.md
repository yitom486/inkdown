## 版本策略总览

| 版本 | 代号 | 范围 | AI | 发布渠道 |
|------|------|------|-----|----------|
| **v0.1.x** | 阅读器版 | Markdown 编辑 + PDF/EPUB/MOBI/AZW3 阅读、书签批注 | ❌ 无 | **GitHub Releases（首要）** |
| **v0.2.x** | Agent 预览 | v0.1 全部 + ACP Client MVP + Codex 适配器 | ⚙️ 可选（用户自备 Key） | GitHub Releases + Release Notes |
| **v0.3.x** | Agent 增强 | fs 回调、权限 diff、多 Agent 配置 | ⚙️ 同上 | 同上 |
| v1.0.0 | 正式版 | 功能冻结、文档齐全、CI 发版自动化 | 稳定可选模块 | 待定（含自动更新再评估） |

**原则：**

1. **安装包不内置 LLM / 不捆绑 API Key** — AI 能力通过 ACP 连接用户本机或自行安装的 Agent 运行时（如 `codex-acp`）。
2. **v0.1 可先发布** — 当前功能已具备「轻量阅读器 + Markdown 编辑器」价值，不阻塞于 AI。
3. **语义化版本** — `MAJOR.MINOR.PATCH`；AI 相关大功能进 MINOR，修复进 PATCH。

### 手动发版步骤（首版 / 备用）

> 日常发版推荐 **打 tag 推送**，由 GitHub Actions 自动打包上传（见下方「自动发版」）。

```bash
# 1. 更新版本号（package.json）
# 2. 验证
bun run test:all

# 3. 提交并打 tag
git add package.json
git commit -m "chore: 发布 v0.1.0"
git tag v0.1.0
git push origin master --tags

# 4. 等待 Actions「Release」工作流完成，或在 GitHub Releases 页查看
```

### 自动发版（已配置）

工作流：[`.github/workflows/release.yml`](./.github/workflows/release.yml)

- **触发**：推送匹配 `v*` 的 tag（如 `v0.1.0`），或 Actions 页手动 Run
- **不会**在普通 `git push` 到 master 时发版
- **产物**：Windows `.exe` + macOS `.dmg`/`.zip` + Linux `.AppImage`/`.deb` 上传至 GitHub Releases

### 触发方式（重要）

| 操作 | 是否打包发版 |
|------|----------------|
| `git push origin master` | ❌ 否（仅运行 [CI](../.github/workflows/ci.yml)） |
| `git push origin v0.1.0` | ✅ 是（运行 [Release](../.github/workflows/release.yml)） |
| GitHub Actions 手动 Run workflow | ✅ 是（基于当前分支 HEAD 打包，**不会**自动改版本号） |

**推荐发版流程：**

```bash
# 1. 更新 package.json 版本号并提交
# 2. 本地验证（可选）
bun run test:all

# 3. 打 tag 并推送（触发自动发版）
git tag v0.1.0
git push origin master
git push origin v0.1.0
```
