> **计划状态**: `pending`  
> **创建日期**: 2026-08-29  
> **最后更新**: 2026-08-29  
> **目标**: 为可编辑的 `.md` 文档提供「旁注 / 批注」能力，服务笔记与研读场景；**不照搬** EPUB/PDF 划词 overlay  
> **优先级**: 低于 [阅读标记与批注](./2026-08-28-阅读标记与批注.md) 收尾、[GitHub 发布](./2026-08-29-GitHub发布与版本路线.md) v0.1、[ACP 客户端](./2026-08-29-ACP客户端.md) 主路径；建议 **v0.3+** 再启动

## 为什么值得做（产品价值）

Markdown 编辑器若只有「写」，缺少「在原文旁留下思考」的闭环。旁注把产品从「文本工具」推向「研读 / 知识整理」：

| 场景 | 价值 |
|------|------|
| 写长文 / 改稿 | 标出待改句、疑问点，不污染正文 |
| 读书笔记（自写 md） | 引用一段 + 写下感想，可检索、可导出 |
| 与电子书批注形成能力对称 | 读 EPUB 能批，写 MD 也能记，心智统一 |
| 后续接 Agent（ACP） | 「根据我的旁注改这一段」是很自然的 Agent 入口 |

**结论**：价值大，但是 **中长期差异化**，不是 v0.1 阻塞项。电子书批注解决「只读内容上的锚点」；Markdown 要解决「正文会变时的旁注」——问题域不同，必须分阶段做。

---

## 明确不做（首版）

| 方案 | 原因 |
|------|------|
| ❌ 直接复用 `reading-marks` 的 DOM overlay / CFI | 编辑一改行，锚点即漂 |
| ❌ 一上来做精确选区浮动批注（类 Google Docs） | 与 CodeMirror 同步、冲突合并成本过高 |
| ❌ 强制把批注写进正文语法（除非用户显式导出） | 污染源文件、破坏预览与 diff |

## 推荐形态（分阶段）

### 阶段 A — 旁注列表 + 原文快照（MVP，优先）

**用户故事**：选中一段 Markdown 文本 →「添加旁注」→ 侧栏出现条目（引用快照 + 笔记正文）→ 点击可尝试跳回原文。

| 项 | 设计 |
|----|------|
| 锚点策略 | 存 `quote`（选中原文快照）+ 可选 `startOffset`/`endOffset`（尽力而为） |
| 正文被改后 | 精确高亮可失效；**快照与笔记仍保留**；提供「在文档中查找引用」 |
| 存储 | 主进程 JSON（建议 `userData/markdown-notes.json`），按 `filePath` 索引；IPC + `Result`；TanStack Query |
| UI | 侧栏「旁注」面板 + 选区工具条（可复用阅读器 `SelectionToolbar` 思路，独立组件） |
| 编辑器 | CodeMirror 6：选区读取；可选 decoration 仅当 offset 仍匹配时显示浅底色 |

### 阶段 B — 预览区只读划词（可选增强）

在 **预览 pane** 划词添加旁注（体验接近电子书）。编辑保存后重新渲染时：用 quote 模糊匹配尝试恢复高亮；失败则降级为「仅列表可见」。

### 阶段 C — 导出与互通（增值）

- 导出为带脚注 / 文末「旁注附录」的 Markdown  
- 可选：与阅读标记面板统一入口（「本书/本文的全部笔记」）  
- 可选：ACP 工具「列出当前文件旁注 / 按旁注修改」

### 阶段 D — 精确选区（仅当 A/B 验证有强需求）

CodeMirror `Decoration` + 变更映射（map positions through transactions）。单独评估，不默认承诺。

## 技术草图（阶段 A）

```
shared/types/markdown-note.ts     # MarkdownNote DTO（quote / offsets / body / timestamps）
electron/services/markdown-notes-service.ts
electron/ipc + shared/ipc + preload
src/api/markdown-notes-api.ts
src/hooks/useMarkdownNotes.ts     # useQuery + mutations
src/components/editor/…           # 选区工具条、旁注侧栏、跳转
```

约束（与 AGENTS.md 一致）：

- 渲染进程不直接 `fs`；统一 `Result` / `CANCELLED`  
- 旁注是 **客户端笔记数据**，可用 Query 拉列表；面板折叠等 UI 态用 Zustand  
- **禁止**把旁注状态塞进 `reading-marks` 表结构硬混用（可读共享 UI 模式，数据模型分开）

## 风险与对策

| 风险 | 对策 |
|------|------|
| 用户期望「改字后高亮仍准」 | 文案与 UI 标明「旁注」；失效时提示「原文已变更，仍可查看快照」 |
| `filePath` 重命名/移动导致丢失 | 后续可加相对工作区路径或文件指纹；MVP 先 path 索引 |
| 与阅读标记 UI 混淆 | 面板文案区分「阅读批注」vs「文档旁注」；存储分文件 |
