## 背景与原则

### 为什么要 ACP

| 方案 | 说明 |
|------|------|
| ❌ 自研 Agent 运行时 | 需维护模型调用、工具链、会话状态，与产品核心（编辑/阅读）无关 |
| ✅ **ACP Client** | 编辑器只做 Client 侧：UI + 环境（工作区、文件、终端）+ JSON-RPC 桥接；Agent 由外部进程提供 |

ACP 是 JSON-RPC 2.0 开放标准。首版对接 **[codex-acp](https://github.com/agentclientprotocol/codex-acp)**（`@agentclientprotocol/codex-acp`），后续可扩展 Gemini CLI、Claude 等适配器。

### 首个运行时：codex-acp

| 项 | 说明 |
|----|------|
| 安装 | `bunx -y @agentclientprotocol/codex-acp` 或全局安装；**npm 包已 bundled Codex**，通常无需单独装 Codex CLI |
| 认证 | `OPENAI_API_KEY` / `CODEX_API_KEY`（推荐）；Electron 内设置 `NO_BROWSER=1` 禁用 OAuth |
| 启动命令 | 主进程 spawn：`bunx -y @agentclientprotocol/codex-acp`（或用户配置路径） |
| 不打包进安装程序 | 用户自备 Agent 与 Key；v0.1 安装包不含 AI |

### 固定约束（与 AGENTS.md 一致）

- 主进程管理 Agent **子进程**与 stdio 传输；渲染进程 **禁止**直接 spawn
- 所有跨进程能力走 IPC + `Result<T, AppError>`
- UI 使用 shadcn/ui + Tailwind；会话 UI 状态可用 Zustand，Agent 消息流用 IPC 事件 + 可选 TanStack Query
- 包管理仅用 **Bun**

## ACP 协议要点（Client 职责）

依据 [官方 Overview](https://agentclientprotocol.com/protocol/overview)：

| 阶段 | Client → Agent | Agent → Client |
|------|----------------|----------------|
| 初始化 | `initialize`（版本/能力协商） | 返回 Agent capabilities |
| 认证 | `authenticate`（若 Agent 要求） | — |
| 会话 | `session/new` 或 `session/load` | — |
| 对话 | `session/prompt` | `session/update` 通知（流式 chunk、工具调用、plan） |
| 中断 | `session/cancel` 通知 | — |

**Client 必须实现的 baseline 回调（Agent 会反向调用 Client）：**

- `session/request_permission` — 工具/写文件等操作前征求用户同意（MVP 可简化为对话框 Allow/Deny）

**首版可选、后续迭代：**

- `fs/readTextFile`、`fs/writeTextFile`（与现有 `file-service` 复用）
- `terminal/*`（Electron 内嵌终端或 defer）
- MCP 服务器注入（`session/new` 参数，P2）

**协议版本策略：**

- MVP 锁定 **protocolVersion: 1**
- v2 draft 仅做调研项，不在首版阻塞

**IPC 通道草案：**

| 通道 | 方向 | 说明 |
|------|------|------|
| `acp:list-runtimes` | invoke | 列出 `agent-registry` 中配置的 Agent |
| `acp:connect` | invoke | spawn + initialize |
| `acp:disconnect` | invoke | 结束会话并 kill 子进程 |

| `acp:cancel` | invoke | 中断当前 turn |
| `acp:session-update` | event | Agent → UI 流式更新 |
| `acp:status-changed` | event | connected / disconnected / error |

## 首个 MVP 范围（建议）

**包含：**

1. 连接 **1 种** Agent 运行时（安装说明写入 README / 计划附录）
2. `initialize` + `session/new` + `session/prompt` + `session/update` 流式展示
3. `session/cancel` + 断开连接
4. `session/request_permission` 简单对话框
5. 工作区 `cwd` 传入

**不包含（明确 out of scope）：**

- 自研 LLM 调用、模型路由
- 完整终端集成、MCP 配置 UI
- 自动 apply diff 到编辑器（仅只读展示 + 手动复制，除非阶段 D 写文件回调已稳定）
- ACP v2-only 特性

## 风险与对策

| 风险 | 对策 |
|------|------|
| Agent 未安装或版本不兼容 | `agent-registry` + 连接前 preflight（`which` / `--version`）；UI 展示安装指引 |
| stdio 阻塞 / 大 payload | 行缓冲 JSON-RPC；单线程读写队列；超大文件 read 限制 |
| Windows 路径与 ACP「绝对路径」要求 | 统一 `path.resolve`；Client 回调内校验前缀在工作区内 |
| 子进程僵尸 | `window-all-closed` / `before-quit` 与 `process-manager.disposeAll()` |
| 协议演进 v1→v2 | 抽象 `AcpProtocolAdapter` 接口，v1 首实现 |
