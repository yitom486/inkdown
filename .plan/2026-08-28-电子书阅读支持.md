# 电子书阅读支持（EPUB / PDF / MOBI）

> **计划状态**: `in-progress`  
> **创建日期**: 2026-08-28  
> **最后更新**: 2026-08-28  
> **目标**: 在现有 Markdown 编辑器基础上，增加**只读**电子书/文档渲染能力（不支持编辑）  
> **产品名称**: 轻量阅读器  
> **关联**: [编辑器功能路线图](./2026-08-28-编辑器功能路线图.md)（v0.0.1 已闭环，本计划为 v0.1.x 新能力）

---

## 需求摘要

| 格式 | 能力 | 编辑 |
|------|------|------|
| `.md` | 现有：编辑 + 预览 | ✅ |
| `.pdf` | 分页阅读、缩放、滚动 | ❌ 只读 |
| `.epub` | 章节导航、流式排版 | ❌ 只读 |
| `.mobi` | 章节阅读（见下方限制） | ❌ 只读 |

**不在首版范围**：AZW / AZW3、DRM 加密书、标注/高亮/书签同步、全文搜索（可后续单独立项）。

---

## 可行性评估

### 总评：**可实现，建议分阶段；MOBI 风险最高**

与当前架构（React 渲染进程 + IPC + 侧栏文件树）兼容。核心变化是引入 **「文档类型」**：Markdown 走现有 `EditorLayout`，电子书走新的 **`ReaderLayout`（只读）**。

```
侧栏选中文件
    │
    ├─ .md / .markdown / .txt  →  EditorLayout（CodeMirror + Preview）
    │
    └─ .pdf / .epub / .mobi    →  ReaderLayout（对应 Viewer 组件）
```

---

### PDF — 可行性：**高** ⭐⭐⭐

| 维度 | 说明 |
|------|------|
| 技术路径 A | **pdf.js**（Mozilla）：在渲染进程 Canvas 绘制，主题/缩放完全可控，与 `contextIsolation` 兼容 |
| 技术路径 B | Chromium 内置 PDF 插件：通过 `BrowserView` / 自定义协议加载 `file://`，实现快但样式与错误处理难统一 |
| 推荐 | **pdf.js**（路径 A），与 EPUB 共用「阅读器工具栏」（缩放、页码） |
| 主进程 | 新增 `readBinaryFile` IPC，或注册 `app-local://` 协议供 pdf.js 拉取本地文件 |
| 体积 | pdf.js  worker + cmaps 约 3–8 MB（可接受，Vite 分包） |
| 风险 | 超大 PDF（>100MB）内存占用；扫描版 PDF 无文字层则无法选中文字（预期行为） |

**结论**：优先实现，1–2 天可出可用 MVP。

---

### EPUB — 可行性：**高** ⭐⭐⭐

| 维度 | 说明 |
|------|------|
| 推荐库 | **epub.js**（社区成熟，流式 reflow 排版） |
| 主进程 | `readBinaryFile` → ArrayBuffer / base64 传给渲染进程 |
| 功能 | 目录（TOC）、章节切换、字体大小、主题（可复用现有 dark/light） |
| 体积 | epub.js + 依赖约 1–3 MB |
| 风险 | 固定版式 EPUB（漫画/绘本）排版可能差；部分内嵌字体需额外加载；加密 EPUB 不支持 |

**结论**：与 PDF 同属第一梯队，体验可做到接近轻量阅读器。

---

### MOBI — 可行性：**中低** ⭐⭐

| 维度 | 说明 |
|------|------|
| 格式复杂度 | MOBI 源于 PalmDOC，后演进 KF7/KF8；纯 JS 生态远弱于 EPUB/PDF |
| 可选方案 1 | **轻量解析**（如 `mobi` / `mobi-parser` 类库）：提取 HTML 片段 + 图片，用统一 Reader 壳渲染 —— **可行但质量不稳定** |
| 可选方案 2 | 捆绑 **Calibre CLI** 转 EPUB 再读 —— 依赖外部程序，安装包体积与许可复杂，**不推荐** |
| 可选方案 3 | 主进程 **native 模块**（libmobi）—— 能力强但跨平台编译、electron-builder 配置成本高 |
| DRM / AZW3 | 首版 **明确不支持** |

| 子格式 | 首版建议 |
|--------|----------|
| 旧版 MOBI（无 KF8） | 可尝试只读，标注「实验性」 |
| AZW / AZW3 | 不做 |
| 转换后 MOBI | 若解析失败，提示用户用 Calibre 转为 EPUB |

**结论**：**不建议与 PDF/EPUB 同批上线**；可作为阶段 3，或首版仅「尝试打开 + 友好失败提示」。

## 与现有代码的衔接点

| 模块 | 现状 | 需改动 |
|------|------|--------|
| `shared/constants.ts` | 仅 `MARKDOWN_EXTENSIONS` | 增加 `READER_EXTENSIONS` / 文档类型枚举 |
| `electron/workspace.ts` | 侧栏只扫描 `.md` 等 | 扩展扫描 `.pdf/.epub/.mobi` |
| `electron/file-service.ts` | `readFile` 仅 utf-8 文本 | 新增 `readBinaryFile`（`readFile` 不带 encoding） |
| `useFileOperations` | 打开文件一律进编辑器 | 按扩展名分支：`loadMarkdown` vs `openReader` |
| `EditorLayout` | 固定编辑+预览 | 上层改为 `DocumentLayout`，按类型切换子布局 |
| 菜单「打开文件」 | Markdown 过滤器 | 增加「所有支持格式」或独立「打开电子书」 |

**无需改动**：Markdown 编辑链、导出 PDF（已有的是「导出」而非「阅读」）、Zustand 视图模式可对只读文档隐藏「编辑/分屏」。

## 推荐技术选型

| 格式 | 库 | 许可 |
|------|-----|------|
| PDF | `pdfjs-dist` | Apache-2.0 |
| EPUB | `epubjs` | BSD-2-Clause |
| MOBI（阶段 3） | 待定，优先评估 `mobi` npm 包解析质量 | 实现前审查 |

**不引入**：Electron `@electron/remote`、渲染进程直接 `fs`、未消毒的 HTML 注入（EPUB 章节 HTML 需 DOMPurify 或 iframe sandbox）。

## 风险与对策

| 风险 | 对策 |
|------|------|
| 渲染进程内存占用高 | 切换文件时销毁 Viewer 实例；PDF 限制同时打开数量 |
| EPUB XSS | iframe `sandbox` + DOMPurify；禁止脚本 |
| MOBI 兼容性差 | 阶段 3 单独交付，UI 标注实验性 |
| 安装包变大 | pdf.js / epub.js 按需动态 import |
| 与 Markdown 状态混淆 | 只读文档不写入 `content` state，独立 `readerStore` |
